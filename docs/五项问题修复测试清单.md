### 2. 取消图片上传

用例文件：[单元测试](../test/image-upload.test.mjs)、[浏览器测试](../test/image-upload.html)。

| 用例 | 操作或条件 | 预期结果 |
| --- | --- | --- |
| 中止请求 | 上传时触发取消 | 调用请求的中止方法，等待以取消结果结束 |

| 上传前已经取消 | 用已取消的任务开始上传 | 不创建网络请求 |

| 图片尚在生成 | 生成图片时按 Escape 关闭，再返回图片生成结果 | 不再发起上传请求 |

用例文件：[单元测试](../test/autosave.test.mjs)、[换乘多窗口测试](../test/storage-conflicts.html)、[自动保存回归](../test/autosave.html)、[导向项目测试](../test/guidance-projects.html)、[站台项目测试](../test/platform-projects.html)。导向与站台现已使用独立项目存储，同一项目的版本检查在数据库事务内完成；换乘沿用单份自动存档检查。

| 用例 | 操作或条件 | 预期结果 |
| --- | --- | --- |
| 取消待保存修改 | 本页等待保存时，其他页面先保存同类型项目 | 本页停止自动保存并显示冲突提示 |
| 存储事件尚未送达 | 保存前发现存档已经改变 | 不覆盖其他页面的存档 |
| 冲突后继续编辑或离开 | 冲突页面继续修改并触发离开事件 | 其他页面的存档保持原样 |
| 导出备份 | 冲突后又修改本页，再点导出备份 | 文件包含本页最新内容 |
| 重新加载 | 点击重新加载入口 | 恢复其他页面已保存的项目 |
| 三个编辑器分别验证 | 各打开两个同类型编辑页面 | 都能提示冲突、备份并重新加载 |

| 旧事件晚到 | 当前存档未变，收到较早的存储事件 | 不误报冲突 |
| 启动时读取失败 | 存储恢复后发现已有其他项目 | 保留备份入口，不覆盖未知内容 |
| 未修改就离开 | 已保存页面再次离开 | 不重复写入旧数据 |
| 原有保存能力 | 连续修改、空间不足、存储禁用、恢复后重试 | 保存时机、失败提示和备份正常 |

### 5. 图床转发服务的使用限制

用例文件：[限制测试](../test/relay-limits.test.mjs)、[原有转发测试](../test/freeimage-relay.test.mjs)。配置见[图片上传说明](image-upload.md)。

| 用例 | 操作或条件 | 预期结果 |
| --- | --- | --- |
| 同一地址频繁请求 | 超过指定时段内的请求次数 | 返回 429 和等待秒数，不转发图片 |
| 伪造访问者地址 | 未配置可信服务器时改变转发请求头 | 不能绕过地址限制 |
| 请求次数到期 | 推进测试时间到下个统计时段 | 可以再次上传 |
| 同时上传过多 | 达到整个服务的同时上传上限后再上传 | 返回 429，已开始的上传正常结束 |
| 释放名额 | 上传成功、转发失败或访问者取消 | 上传名额释放，后续上传可继续 |
| 取消转发 | 访问者在转发中取消请求 | 发往图床的请求也被中止 |
| 地址和服务总上传量 | 分别达到各自配额，再等到下一时段 | 超限返回 429，到期后恢复 |
| 接收过程中超额 | 表单接收时超过配额 | 立即拒绝，不向图床转发 |
| 无效表单反复提交 | 先提交错误表单，再提交图片 | 错误请求同样计入请求次数 |
| 可信服务器提供地址 | 指定可信服务器，分别发送两个访问者地址 | 每个地址分别计数；伪造前面的地址无效 |
| 无效地址头 | 可信服务器提供格式错误的地址 | 按连接地址计数，不能借此绕过限制 |
| 地址记录过多 | 达到记录数量上限，随后等待记录过期 | 先返回 429，清理过期记录后可继续 |
| 错误配置 | 使用 0、负数、小数或无效地址 | 启动检查明确拒绝 |
| 原有转发能力 | 来源检查、表单检查、图片大小、固定目标、上游错误、超时和错误信息 | 全部通过，响应不暴露密钥 |

## 复查方法

在仓库根目录运行：

```powershell
node --test --experimental-test-coverage --test-coverage-exclude="vendor/**" --test-coverage-exclude="test/**" test/*.test.mjs
python -m http.server 8000
```

浏览器打开上表的测试页面，等页面标题显示通过或失败。浏览器测试应使用独立的测试地址或独立窗口，测试过程中会写入同源浏览器存储。

推送前复查记录保存在本地 `.release-checks/five-fixes-push-coverage.log` 和 `.release-checks/five-fixes-push-final-browser-results.json`。首次修复时的记录仍保留在以 `five-fixes-` 开头的其他文件中。
